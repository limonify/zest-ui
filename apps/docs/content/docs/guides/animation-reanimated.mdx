---
title: Animating with Reanimated
description: Drive zest's animation contract with react-native-reanimated instead of RN Animated.
---

zest never animates. Instead, every animated part publishes its **transition status** and its
**measured geometry** on the state object, and you drive the animation. The docs use RN's built-in
`Animated`, but [`react-native-reanimated`](https://docs.swmansion.com/react-native-reanimated/) is
a natural fit — and often cleaner, because its layout animations don't need a measured height at all.

<Callout type="info">
  Every animated component's page has its own **Animation** section with a part-specific snippet
  (Dialog fade, Drawer slide, Collapsible height, Tabs indicator, Switch thumb, and more). This guide
  is the shared contract and the reusable recipes behind them.
</Callout>

## On the web

Reanimated runs in a browser, and it interpolates for real rather than jumping — measured on this
repo's example app exported with `expo export --platform web`: 120 ms into a 250 ms `withTiming`, the
transform was two thirds of the way there.

What it needs is **Expo's bundler**. Its Babel plugin is what turns your worklets into something a
browser can run, and `babel-preset-expo` includes it. Bundlers that do not run Babel — Next.js with
Turbopack, which is what these docs are built with — cannot resolve it: Reanimated deep-imports
`react-native/Libraries/…` and `TurboModuleRegistry`, neither of which survives an alias to
`react-native-web`. Worse, merely *installing* it is enough to break such a build, because
`react-native-gesture-handler` imports Reanimated whenever it can resolve it — so a `Slider` stops
bundling too.

If you are putting zest on the web outside Expo, RN's built-in `Animated` is the option with no
setup at all: `react-native-web` implements it, and it is what the live demos on these pages use.

## Enter / exit with layout animations

For a `Dialog`, `Drawer`, `Popover`, `Menu` or `Toast`, the simplest approach is Reanimated's
`entering`/`exiting` presets. Keep the part mounted through the exit with `keepMounted`, and read
`state.transitionStatus` to decide when to play the exit.

```tsx
import Animated, { FadeIn, FadeOut, SlideInDown, SlideOutDown } from 'react-native-reanimated';
import { Dialog } from '@limonify/zest-ui';

<Dialog.Popup
  keepMounted
  render={(props, state) => (
    <Animated.View
      {...props}
      entering={FadeIn.duration(150)}
      exiting={FadeOut.duration(150)}
    />
  )}
>
  {/* ... */}
</Dialog.Popup>
```

`transitionStatus` is `'starting' | 'idle' | 'ending' | undefined`; `state.mounted`-style unmounting
is handled by `keepMounted`. Because React Native can't report when an exit animation finished,
`keepMounted` is what keeps the element around long enough for `exiting` to play.

### The Modal stays out of your way

Every popup family's `Portal` is a React Native `Modal`, and its `animationType` defaults to
`"none"` — nothing native runs underneath what you animate. That is the whole point: a platform
cross-fade competes with your enter and tears the surface away mid-exit on close.

You do not have to do anything for this. If you would rather hand the transition back to the
platform — reasonable when you are *not* animating the popup yourself, since the native fade also
covers the exit that a consumer-driven animation cannot — ask for it through
[`modalProps`](/docs/common-props#modalprops--on-every-portal):

```tsx
<Dialog.Portal modalProps={{ animationType: 'fade' }}>
```

## Less boilerplate: `useAnimatedValue`

Every state-driven animation repeats the same three steps — a shared value, a `useEffect` that
`withTiming`s it to a target, and a `useAnimatedStyle`. Collapse the first two into one small hook,
copied once into your app (e.g. `useAnimatedValue.ts`). It also reads `useReducedMotion()`, so every
call respects the OS **Reduce Motion** setting for free:

```tsx
import { useEffect } from 'react';
import {
  useSharedValue,
  withTiming,
  useReducedMotion,
  type SharedValue,
  type WithTimingConfig,
} from 'react-native-reanimated';

export function useAnimatedValue(target: number, config?: WithTimingConfig): SharedValue<number> {
  const reduceMotion = useReducedMotion();
  const value = useSharedValue(target);
  useEffect(() => {
    value.value = reduceMotion ? target : withTiming(target, config);
  }, [target, reduceMotion]);
  return value;
}
```

Every per-component **Animation** snippet below (and on each component page) uses it. All that's left
is the component-specific `useAnimatedStyle` — Reanimated's irreducible part.

## Collapsible / Accordion height

`Collapsible.Panel` and `Accordion.Panel` publish their measured content height on `state.height`.
Drive a value from `state.open` and clip to it:

```tsx
import Animated, { useAnimatedStyle } from 'react-native-reanimated';
import { useAnimatedValue } from './useAnimatedValue';
import { Collapsible } from '@limonify/zest-ui';

function Panel({ props, state }) {
  const p = useAnimatedValue(state.open ? 1 : 0);
  const style = useAnimatedStyle(() => ({
    // `undefined` — never `0` — until the content has been measured, so the
    // panel falls back to its natural height instead of collapsing shut.
    height: state.height != null ? p.value * state.height : undefined,
    opacity: p.value,
  }));
  // Keep `props.style` in the array: it carries the panel's own `overflow:
  // 'hidden'`, and dropping it is what turns a height animation into a panel
  // whose content spills out of the clip.
  return <Animated.View {...props} style={[props.style, style]} />;
}

<Collapsible.Panel keepMounted render={(props, state) => <Panel props={props} state={state} />}>
  {/* ... */}
</Collapsible.Panel>
```

<Callout type="info">
  Prefer `entering`/`exiting` or Reanimated's `LinearTransition` over animating a measured height
  when you can — measuring a clipped element is fragile on the New Architecture. The measured height
  is there when you need precise control.
</Callout>

### When the panel content is invisible

Almost always one of three things, all on the consumer's side of the contract:

1. **The height resolved to `0` before the content was measured.** `state.height` is `undefined`
   until the panel's inner wrapper reports an `onLayout`. Writing `height: state.height ?? 0` (or
   passing `undefined` into `withTiming`, which yields `NaN`) clips the panel shut on the first
   frame, and a clipped panel can fail to produce a new measurement on the New Architecture — so it
   never reopens. Fall back to `undefined`, not `0`.
2. **`props` was not spread onto the animated view.** The panel delivers its children *through*
   `props.children`; a wrapper that renders `<Animated.View style={style} />` without `{...props}`
   renders an empty box. Spread `props` first, then compose styles on top.
3. **`keepMounted` is missing but an exit animation is expected.** Without it the panel unmounts the
   instant it closes, so the exit never plays and the content appears to vanish rather than animate.

If you only need a fade or a slide, animate `opacity`/`transform` instead and let the panel size
itself — that path does not depend on measurement at all, and it is what `apps/example` uses.

## Timing vs spring

Reach for `withTiming` when the animation has a defined start and end — enter/exit fades, a measured
height opening, an indicator sliding to a known position:

```tsx
progress.value = withTiming(state.open ? 1 : 0, { duration: 200 });
```

Reach for `withSpring` when the target is a physical resting point the user threw something toward —
a thumb settling after a drag, a sheet snapping to a detent:

```tsx
offset.value = withSpring(target, { damping: 18, stiffness: 180 });
```

## Respect reduced motion

Users who enable *Reduce Motion* should get the end state instantly. `useAnimatedValue` above already
handles this — it reads `useReducedMotion()` and assigns the target directly instead of animating, so
every example that uses the hook is covered. For `entering`/`exiting` presets, pass
`.reduceMotion(ReduceMotion.System)` (or gate them on `useReducedMotion()` yourself).

## Gesture-following values

`Slider`, `Drawer` and `Toast` are built on `react-native-gesture-handler`, and publish their live
drag on the state object — `Drawer.Popup` and `Toast.Root` as `state.swipeMovement`, `Slider` as
`state.values` (plus `state.dragging`). Feed those straight into a shared value for a sheet or thumb that tracks the finger
and springs home on release:

```tsx
import Animated, { useSharedValue, useAnimatedStyle, withSpring } from 'react-native-reanimated';
import { useEffect } from 'react';
import { Drawer } from '@limonify/zest-ui';

function Sheet({ props, state }) {
  const drag = useSharedValue(0);

  useEffect(() => {
    // Follow the finger 1:1 while dragging, spring back to 0 when released.
    drag.value = state.swipeMovement ? state.swipeMovement : withSpring(0, { damping: 20 });
  }, [state.swipeMovement]);

  const animatedStyle = useAnimatedStyle(() => ({ transform: [{ translateY: drag.value }] }));

  return <Animated.View {...props} style={[props.style, animatedStyle]} />;
}

<Drawer.Popup render={(props, state) => <Sheet props={props} state={state} />} />
```

<Callout type="info">
  The gesture drives dismissal on its own — this only adds the visual follow. Combine it with the
  `entering`/`exiting` slide presets above for the open/close transition.
</Callout>

## Sequencing after a transition (`onOpenChangeComplete`)

zest never animates, so it cannot know when *your* enter or exit animation finished — and most
overlays need to sequence something after a close (reset state, open the parent, unmount). Every
popup root (`Dialog`, `Drawer`, `Popover`, `Tooltip`, `Menu`, `Select`, `Combobox`, …) accepts
`onOpenChangeComplete`, and the consumer reports the settle through the store:

```tsx
import Animated, { FadeIn, FadeOut } from 'react-native-reanimated';
import { useDialogRootContext } from '@limonify/zest-ui';

function Popup({ props }) {
  const store = useDialogRootContext();

  return (
    <Animated.View
      {...props}
      entering={FadeIn.duration(150)}
      // Report when the exit is done so `onOpenChangeComplete` can fire.
      exiting={FadeOut.duration(150).withCallback(() => store.settled(false))}
    />
  );
}

<Dialog.Root onOpenChangeComplete={(open) => console.log('settled', open)}>
  <Dialog.Portal keepMounted>
    <Dialog.Popup render={(props) => <Popup props={props} />} />
  </Dialog.Portal>
</Dialog.Root>
```

Keep the popup mounted through the exit — `keepMounted` on the `Portal` (or the part's own lever,
e.g. `Toast.Root`'s `removeOnClose`) — otherwise the tree unmounts before the exit can play. The
`settled(open)` call fires `onOpenChangeComplete` once per settle, carrying the reason of the last
committed open/close.

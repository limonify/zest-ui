## Install

```bash
bun add @limonify/zest-ui
# or: npm install @limonify/zest-ui
```

### Peer dependencies

zest needs React 19+ and React Native 0.79+, plus `react-native-gesture-handler`, which is a
**required** peer.

On Expo, install it through Expo so you get the version your SDK ships — Expo Go bundles a fixed
native build of it, and a JS version that does not match crashes at gesture attach with
`undefined is not a function`, long after the bundle succeeded:

```bash
npx expo install react-native-gesture-handler
```

Anywhere else:

```bash
bun add react-native-gesture-handler
```

### Why it is required, and when you must wrap the app

Five parts are built on gestures — `Slider.Control`, `Drawer.Popup`, `Drawer.SwipeArea`,
`Toast.Root` and `NumberField.ScrubArea` — and each imports the library at the top level.

The package is required rather than optional because the package root re-exports every component
and Metro does not tree-shake, so `import { Dialog } from '@limonify/zest-ui'` pulls the gesture
parts into the bundle whether you render them or not. A per-component subpath does not:

```tsx
import { Dialog } from '@limonify/zest-ui/dialog';   // no gesture handler in this graph
```

**Wrapping the app is a separate question.** `GestureHandlerRootView` is only needed if you
actually render one of those five parts. Without it they throw
`GestureDetector must be used as a descendant of GestureHandlerRootView`; every other component
works without it:

```tsx
import { GestureHandlerRootView } from 'react-native-gesture-handler';

export default function App() {
  return <GestureHandlerRootView style={{ flex: 1 }}>{/* ... */}</GestureHandlerRootView>;
}
```

Anchored popups (`Popover`, `Tooltip`, `Menu`, `Select`, `Combobox`) use
`@floating-ui/react-native`, which ships as a regular dependency — nothing to install.

## Providers

Most components need no provider. The one exception is **Toast**: it is not a Modal (so the app
underneath stays usable), which means it needs a `Toast.Provider` and a `Toast.Viewport` mounted
once at the root, near your `GestureHandlerRootView`:

```tsx
import { GestureHandlerRootView } from 'react-native-gesture-handler';
import { Toast } from '@limonify/zest-ui';

export default function App() {
  return (
    <GestureHandlerRootView style={{ flex: 1 }}>
      <Toast.Provider timeout={4000} limit={3}>
        <RootNavigator />
        <Toast.Viewport style={{ paddingHorizontal: 16, paddingBottom: 48 }}>
          {/* render your toasts here — see the Toast page */}
        </Toast.Viewport>
      </Toast.Provider>
    </GestureHandlerRootView>
  );
}
```

Skip `GestureHandlerRootView` if you use neither Slider nor Drawer, and skip `Toast.Provider` if you
don't use toasts.

## Your first component

Import a `Root` and its parts, and style them with your own `StyleSheet`:

```tsx
import { StyleSheet } from 'react-native';
import { Switch } from '@limonify/zest-ui';

export function DarkModeToggle() {
  return (
    <Switch.Root style={(state) => [styles.track, state.checked && styles.trackOn]}>
      <Switch.Thumb style={(state) => [styles.thumb, state.checked && styles.thumbOn]} />
    </Switch.Root>
  );
}

const styles = StyleSheet.create({
  track: { width: 44, height: 26, borderRadius: 13, backgroundColor: '#d4d4d4', padding: 3 },
  trackOn: { backgroundColor: '#4c7a0b' },
  thumb: { width: 20, height: 20, borderRadius: 10, backgroundColor: '#fff' },
  thumbOn: { transform: [{ translateX: 18 }] },
});
```

## Importing

Everything is exported from the package root, which is the simplest thing to reach for:

```tsx
import { Dialog, Form, DirectionProvider } from '@limonify/zest-ui';
```

Every component and utility also has its own subpath, which is what a bundler needs to drop the
rest of the library:

```tsx
import { Dialog } from '@limonify/zest-ui/dialog';
import { Form } from '@limonify/zest-ui/form';
import { DirectionProvider } from '@limonify/zest-ui/direction-provider';
import { useFilter } from '@limonify/zest-ui/filter';
```

The subpath is the component's directory name — `alert-dialog`, `number-field`, `radio-group` and
so on — plus `filter`, `hooks`, `store`, `use-render`, `merge-props` and `types`. Metro resolves
these to the source through the package's `react-native` condition and transforms it with your own
Babel; everyone else gets the compiled `lib/`.

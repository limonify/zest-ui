`Field` wires a label, a text input, a description and validation together for accessibility. Validation is a `validate` function (React Native has no HTML constraint API).

## Usage

Press it, then read it. The behaviour is headless — the **Code** tab is the component; the **StyleSheet** and **Uniwind** tabs are two ways to design it.

## API

`Field` — the props below sit on the root. Every part also accepts the [common props](/docs/common-props) (`style`/`className` as a value or function of state, `render`, `ref`).

### Slowing validation down

With `validationMode="onChange"`, `validate` runs on every keystroke — fine for a cheap check,
wasteful for anything else, and it makes the error flicker while the user is still typing.
`validationDebounceTime` waits instead:

```tsx
<Field.Root validationMode="onChange" validationDebounceTime={300} validate={checkUsername}>
```

A blur, or a form submitting, validates immediately and cancels whatever is pending — so nothing
can submit against a stale verdict.

### Labelling each item of a group

A `Field.Root` labels one control, so a checkbox or radio group inside it would have every item
pointing at the same label. `Field.Item` opens a nested labelling scope: the `Field.Label` and
`Field.Description` inside it associate with *its* control and nothing else, while validity,
`disabled` and the rest still come from the surrounding field.

```tsx
<Field.Root>
  <Field.Label>Notifications</Field.Label>
  <CheckboxGroup value={value} onValueChange={setValue}>
    <Field.Item style={styles.row}>
      <Checkbox.Root value="email" />
      <Field.Label>Email</Field.Label>
      <Field.Description>At most one digest a day</Field.Description>
    </Field.Item>
    <Field.Item style={styles.row}>
      <Checkbox.Root value="sms" />
      <Field.Label>SMS</Field.Label>
    </Field.Item>
  </CheckboxGroup>
</Field.Root>
```

An item can be `disabled` on its own; a disabled `Field.Root` disables all of them.

### Which controls a field wires up

`Field.Control` and `Input` are the text inputs. Beyond those, `Checkbox`, `Switch`, `RadioGroup`,
`Slider`, `NumberField`, `OTPField`, `Select`, `Combobox` and `Autocomplete` all report themselves
to a surrounding field: they inherit its `disabled`, are named by `Field.Label`, run its `validate`,
and take part in a [`Form`](/docs/components/form).

`Field.Error` publishes every message on its state, so a `validate` that returns several can render
them all — `children` defaults to the first:

```tsx
<Field.Error render={(props, state) => (
  <View {...props}>
    {state.errors.map((message) => <Text key={message}>{message}</Text>)}
  </View>
)} />
```

Pass `match` to keep it rendered regardless of validity — that is this part's `keepMounted`.

### What counts as a control

`Field.Control` and [`Input`](/docs/components/input) are the text controls, but a field also picks
up **Checkbox**, **Switch**, **RadioGroup**, **NumberField**, **Slider**, **Select** and
**OTPField**. Each of them inherits the field's `disabled`, is labelled by `Field.Label`, described
by `Field.Description`/`Field.Error`, and runs `validate` as its value changes.

They report `dirty`, `filled` and `touched` too, so `Field.Validity` reads the same for a checkbox
as for a text input:

```tsx
<Field.Root validate={(value) => (value ? null : 'Pick a plan')}>
  <Field.Label>Plan</Field.Label>
  <RadioGroup>{/* … */}</RadioGroup>
  <Field.Validity>
    {({ field, errors }) => (field.touched && errors.length > 0 ? <Text>{errors[0]}</Text> : null)}
  </Field.Validity>
</Field.Root>
```

Since none of these blur the way a text input does, "touched" is the end of the interaction:
committing a press for a checkbox or radio, releasing the thumb for a slider, closing the popup for
a select, completing the code for an OTP field.

## Accessibility

The control is labelled by `Field.Label` and described by `Field.Description`/`Field.Error` via `accessibilityLabelledBy`/`accessibilityDescribedBy`. `validationMode` runs `validate` on blur or change. `Checkbox`, `Switch`, `RadioGroup` and `NumberField` are also field-aware.

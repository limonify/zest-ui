`Slider` is a value (or range) selector driven by a drag gesture. It needs `react-native-gesture-handler` and the app wrapped in `GestureHandlerRootView`.

## Animation

The built-in gesture already moves the thumb live, so you rarely animate its position. Instead react to `state.dragging` (on `Slider.Thumb`) — for example, grow the thumb while it is held:

```tsx
import Animated, { useAnimatedStyle } from 'react-native-reanimated';
import { useAnimatedValue } from './useAnimatedValue'; // small helper — see the guide
import { Slider } from '@limonify/zest-ui';

function Thumb({ props, state }) {
  const scale = useAnimatedValue(state.dragging ? 1.25 : 1, { duration: 120 });
  const style = useAnimatedStyle(() => ({ transform: [{ scale: scale.value }] }));
  return <Animated.View {...props} style={[styles.thumb, style]} />;
}

<Slider.Thumb render={(props, state) => <Thumb props={props} state={state} />} />
```

To make the thumb *follow* the finger with spring physics instead, feed `state.values` into a shared value — see **Gesture-following values** in the [Reanimated guide](/docs/guides/animation-reanimated).

### Following the finger on the UI thread

The built-in drag updates the value through React: the gesture's handlers touch the store, so they
run on the JS thread (`.runOnJS(true)`), and the thumb's position comes out of `state.value`. On a
busy JS thread that round trip lands on **every frame of a drag**, and the thumb visibly lags the
finger.

zest will not animate for you and takes no animation dependency, so the fix is to let you attach a
gesture of your own that stays on the UI thread. `Slider.Control` runs it alongside its own with
`Gesture.Simultaneous`, so the value keeps updating exactly as before while your thumb follows the
touch with no render in the path.

The conversion you need is exported, so it cannot drift from the one the store runs:

```tsx
import { Gesture, GestureDetector } from 'react-native-gesture-handler';
import Animated, { useAnimatedStyle, useSharedValue } from 'react-native-reanimated';
import { Slider, sliderPercentFromValue, sliderValueFromPosition } from '@limonify/zest-ui';

function LiveSlider() {
  const percent = useSharedValue(0);
  // `controlSize`, `min`, `max`, `step`, `orientation` and `direction` all reach
  // you on the state object; capture them where you build the gesture.
  const geometry = { controlSize, orientation, direction, min, max, step };

  const follow = React.useMemo(
    () =>
      Gesture.Pan().onUpdate((event) => {
        'worklet';
        const value = sliderValueFromPosition(event.x, geometry);
        if (value !== undefined) {
          percent.value = sliderPercentFromValue(value, geometry.min, geometry.max);
        }
      }),
    [geometry, percent],
  );

  const thumbStyle = useAnimatedStyle(() => ({ left: `${percent.value * 100}%` }));

  return (
    <Slider.Root defaultValue={40}>
      <Slider.Control simultaneousGesture={follow}>
        <Slider.Track>
          <Slider.Thumb render={(props) => <Animated.View {...props} style={[props.style, thumbStyle]} />} />
        </Slider.Track>
      </Slider.Control>
    </Slider.Root>
  );
}
```

`onValueChange`, `state.value` and the rendered thumb position are unchanged for anyone who does
not pass `simultaneousGesture` — this is opt-in, and costs nothing when unused.

### Smooth drags without Reanimated

The built-in drag already moves the thumb (zest positions it with a percentage, updated from the
committed value each frame), so most sliders never animate their thumb's position at all. If you
want a native-driver follow instead — RN's `Animated` with `useNativeDriver: true` runs the
transform on the UI thread, no Reanimated — place the thumb yourself and let the driver move it:

```tsx
import * as React from 'react';
import { Animated, StyleSheet } from 'react-native';
import { Slider } from '@limonify/zest-ui';

const THUMB_WIDTH = 24;

function Thumb({ props, state, trackWidth }) {
  const translateX = React.useRef(new Animated.Value(0)).current;

  React.useEffect(() => {
    // `duration: 0` — the commit already happens each frame; the driver just
    // applies it on the UI thread instead of going through JS layout.
    Animated.timing(translateX, {
      toValue: ((trackWidth - THUMB_WIDTH) * (state.value - state.min)) / (state.max - state.min),
      duration: 0,
      useNativeDriver: true,
    }).start();
  }, [state.value, state.min, state.max, trackWidth, translateX]);

  return (
    // `left: 0` overrides zest's own percentage positioning (your style wins),
    // so the thumb starts at the track's start and the transform does the rest.
    <Animated.View {...props} style={[styles.thumb, { transform: [{ translateX }] }]} />
  );
}

// `trackWidth` comes from your own `onLayout` on `Slider.Control`; the styles.thumb
// must carry `position: 'absolute', left: 0` to take over from zest's placement.
```

Two caveats: `useNativeDriver` only animates `transform`/`opacity` (never `left`), and the drag's
value still commits on the JS thread — the native driver smooths the *visual*, it does not move the
value off the thread.

Reanimated drops right in for the same job — `useAnimatedStyle` reads the same `state.value` on the
UI thread and needs no `trackWidth` bookkeeping. The two are interchangeable because zest only
publishes state; it never dictates which animation library you bring.

### A Reanimated thumb

The same follow, written with Reanimated instead of RN's `Animated`. `useAnimatedStyle` runs on the
UI thread, so the transform never waits on a JS render:

```tsx
import * as React from 'react';
import { StyleSheet } from 'react-native';
import Animated, { useAnimatedStyle, useSharedValue } from 'react-native-reanimated';
import { Slider } from '@limonify/zest-ui';

const THUMB_WIDTH = 24;

function Thumb({ props, state, trackWidth }) {
  const position = useSharedValue(0);

  React.useEffect(() => {
    // `state.value` commits once per frame; copying it into a shared value is
    // what lets the style below read it off the JS thread.
    position.value =
      ((trackWidth - THUMB_WIDTH) * (state.value - state.min)) / (state.max - state.min);
  }, [position, state.value, state.min, state.max, trackWidth]);

  const animatedStyle = useAnimatedStyle(() => ({
    transform: [{ translateX: position.value }],
  }));

  // `left: 0` overrides zest's percentage placement (your style wins), and the
  // transform does the rest.
  return <Animated.View {...props} style={[styles.thumb, animatedStyle]} />;
}

<Slider.Thumb render={(props, state) => <Thumb props={props} state={state} trackWidth={width} />} />
```

`trackWidth` is the consumer's own `onLayout` on `Slider.Control`; `styles.thumb` must carry
`position: 'absolute', left: 0`. The value still commits on the JS thread — for a follow that never
touches JS during the drag, feed `state.values` into the gesture-following pattern in the
[Reanimated guide](/docs/guides/animation-reanimated) instead.

A drag also re-renders only the parts whose values changed: each thumb subscribes to its own value,
so in a range slider a drag re-renders the thumb being moved, the indicator and the value text —
not every thumb on the track.


## Inside a Field

Wrapped in a [`Field.Root`](/docs/components/field), the slider inherits its `disabled` and
`Slider.Thumb` is labelled by `Field.Label` — the thumb rather than the root, because that is the
element assistive technology announces and adjusts. `Slider.Label` is still the fallback for a
slider that stands on its own. Dragging marks the field dirty; releasing the thumb marks it
touched, which is when `validationMode="onBlur"` runs.

## Accessibility

Pass an array `value` for a range slider. Each `Slider.Thumb` is `accessibilityRole="adjustable"` and labelled by `Slider.Label`. Requires `react-native-gesture-handler`.

### What a screen reader reads out

Each thumb announces its value through `accessibilityValue.text`, formatted by `format`/`locale`.
`getAccessibilityValueText` replaces it — the third argument is the thumb's index, so the two ends
of a range can read differently:

```tsx
<Slider.Root
  value={[20, 80]}
  getAccessibilityValueText={(text, value, index) =>
    `${index === 0 ? 'Minimum' : 'Maximum'} ${text}`
  }
/>
```

This is upstream's `getAriaValueText`, renamed: React Native has `accessibilityValue.text`, not
`aria-valuetext`. `Progress` and `Meter` carry the same prop.

### Range thumbs colliding

A range slider's thumbs have to do *something* when one is dragged into another, and
`thumbCollisionBehavior` picks what:

- **`'push'`** (default) — the dragged thumb pushes the ones in its way along the track, stopping
  when the thumb it is pushing runs out of room.
- **`'swap'`** — thumbs trade places when one is dragged past another. The drag keeps hold of the
  thumb the finger started on, so dragging past and back returns it where it came from.
  `minStepsBetweenValues` is not enforced while they cross: thumbs allowed to pass each other
  cannot be held apart while they do it.
- **`'none'`** — a thumb stops at its neighbour and the excess movement is dropped.

`thumbAlignment` has no counterpart here. On the web it is CSS inset positioning for the thumb at
`min`/`max`; zest is headless, so you place the thumb yourself from `state.values`.

### Right-to-left

`Slider.Root` reads the direction from [`DirectionProvider`](/docs/utilities/direction-provider), or
takes a `direction` prop of its own. Under `rtl` a horizontal track runs from the right, so both the
touch-to-value mapping and the positioning flip: `Slider.Thumb` and `Slider.Indicator` anchor with
`right` instead of `left`. Your own styles should stay off those two properties for the same
reason — position from `state.values` and let the part place itself.

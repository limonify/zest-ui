`Autocomplete` is a `Combobox` in free-text mode: the typed string **is** the value, and choosing a suggestion fills the input rather than selecting a bound value. It reuses every combobox part.

## Anatomy

            Autocomplete.GroupLabel

`Autocomplete.Group`/`Collection` are only for grouped `items`; a flat list renders items straight
from `Autocomplete.List`. The chip parts a combobox has are absent here on purpose — an
autocomplete's value *is* the typed text, so there is no separate selection to render.

## Usage

The behaviour is headless — the **Code** tab is the component; the **StyleSheet** and **Uniwind** tabs are two ways to design it.

### Clearing, grouping and announcing

These three parts are the combobox's, and behave the same here:

- **`Autocomplete.Clear`** empties the input. It renders nothing while the input is empty; pass
  `keepMounted` to hide it with a style instead. It does not return focus to the input, unlike the
  web version — with `openOnFocus` that would reopen the list.
- **`Autocomplete.Group`/`GroupLabel`/`Collection`** render grouped `items`. An entry becomes a
  group when it carries its own `items`; filtering runs inside each group and drops the ones left
  empty. `isComboboxGroup` tells an entry from a group.
- **`Autocomplete.Status`** is a polite live region announcing how many suggestions are left —
  filtering never moves focus, so nothing else tells a screen reader the list changed.

See [Combobox](/docs/components/combobox) for the worked examples; each one applies here.

### Cancelling a change, and opening it from elsewhere

An autocomplete shares the combobox's event contract: every callback receives an event details
object whose `cancel()` vetoes the change, and `reason` says what caused it. It has a handle too —
`Autocomplete.createHandle()` — for an input rendered outside the root, plus `actionsRef` for
imperative `close()`/`unmount()`. See
[Combobox](/docs/components/combobox) for the worked examples; every one of them applies here.

## Animation

`Autocomplete.Popup` publishes `state.transitionStatus`. Keep the portal mounted with `<Portal keepMounted>` and fade the list in and out:

```tsx
import Animated, { FadeIn, FadeOut } from 'react-native-reanimated';
import { Autocomplete } from '@limonify/zest-ui';

<Autocomplete.Popup render={(props) => (
  <Animated.View {...props} entering={FadeIn.duration(120)} exiting={FadeOut.duration(120)} />
)}>
  {/* ... */}
</Autocomplete.Popup>
```

See the [Reanimated guide](/docs/guides/animation-reanimated) for the full contract.

## Inside a Field

An autocomplete reports itself to a surrounding [`Field.Root`](/docs/components/field), with one
difference from a combobox: its value *is* the typed text, so that is what the field validates and
what a [`Form`](/docs/components/form) submits.

```tsx
<Field.Root name="tag" validate={(text) => (text ? null : 'Add a tag')}>
  <Field.Label>Tag</Field.Label>
  <Autocomplete.Root items={TAGS} inputValue={tag} onInputValueChange={setTag}>
    <Autocomplete.Input />
    {/* … */}
  </Autocomplete.Root>
  <Field.Error />
</Field.Root>
```
